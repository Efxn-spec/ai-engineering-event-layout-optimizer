# Week 1 Project Scope

|  |  |
|---|---|
| **Project Name** | EventLayout-RL: AI Event Layout Optimizer |
| **Domain** | Event Planning / Venue Layout Design |
| **Problem Statement** | Event organizers have a 2D floor plan of the hall, but must decide by hand where the stage, seats and tables go. The layout must be **safe** (clear paths to exits), **compact** (everyone seated without wasting space), give a **clear view of the stage**, and be **practical** (AV table near power, registration near the entrance). These goals conflict and change with every room, so manual planning is slow and mistakes are easy to miss.<br>AI engineering makes it possible to read the floor-plan image, let a reinforcement learning (RL) agent arrange the items until the layout passes the safety and compactness checks, and explain why the final layout is usable. |
| **Evidence of the Problem** | **Evidence 1:** The seating arrangement changes how fast people can evacuate. In a study testing 8 seating arrangements with 15 different exit-door positions, the best arrangement changed depending on where the exits were, so every room needs its own check.<br>**Source / citation:** Delcea, C., et al. (2019). Establishing the proper seating arrangement in elevated lecture halls for a faster evacuation process. *IEEE Access, 7*. <https://doi.org/10.1109/ACCESS.2019.2909637><br>**Evidence 2:** Fitting people compactly into a room under spacing rules is difficult. A concert venue needed a mathematical optimisation model to plan its seating safely, and used the result to stay open.<br>**Source / citation:** Blom, D., Pendavingh, R., & Spieksma, F. (2022). Filling a theater during the COVID-19 pandemic. *INFORMS Journal on Applied Analytics, 52*(6). <https://doi.org/10.1287/inte.2021.1104> |
| **Initial Related Work / Existing Approaches** | 1. **Event diagramming software** (e.g., Cvent / Social Tables): <https://www.cvent.com/en/event-management-software/cvent-event-design-software><br>Key limitation: the organizer still places every item by hand; there is no automatic safety or compactness check.<br>2. **Seat-planning optimisation tools** (Bortolete et al., 2022, *Computational and Applied Mathematics*): <https://doi.org/10.1007/s40314-021-01718-w><br>Key limitation: only places seats; ignores exit paths, the stage and equipment.<br>3. **RL for furniture layout** (Di & Yu, 2021, arXiv:2101.07462): <https://arxiv.org/abs/2101.07462><br>Key limitation: designed for home furniture; no safety rules and no explanation for the user.<br>4. **Generative AI image tools** (Huang et al., 2023, *T2I-CompBench*, NeurIPS): <https://arxiv.org/abs/2307.06350><br>Key limitation: weak at placing objects in the right position and drawing the right number of items, and does not check safety. |
| **Engineering Gap / Limitation** | No existing approach takes a floor-plan image and automatically produces a complete event layout that is both **safe and compact**, and explains **why** it is usable. Existing tools are either manual, handle only seats, ignore safety, or cannot be trusted with exact positions and counts. |
| **Initial Project Objectives** | **O1:** To develop a floor-plan reader (OpenCV) that converts a 2D floor-plan image into a grid map of walls, pillars, exits and power points, which the user can check and correct.<br>**O2:** To develop an RL agent (Maskable PPO) that places the stage, seating blocks, registration table and AV table until the layout is safe, compact, has a clear view of the stage and is practical.<br>**O3:** To evaluate the layouts (layout validity, constraint satisfaction and computation time) against a simple rule-based method, and show the reasons behind each layout. |
| **Target Users** | Event organizers, such as university faculty and student society event committees, planning seminars or conferences of 50–200 people in indoor halls. |
| **Data Sources** | **Source 1:** Fire Safety Risk Assessment: Small and Medium Places of Assembly (UK Government), used for exit and aisle rules. URL: <https://www.gov.uk/government/publications/fire-safety-risk-assessment-small-and-medium-places-of-assembly><br>**Source 2:** CubiCasa5K floor-plan dataset, real floor-plan images for testing the reader. URL: <https://github.com/CubiCasa/CubiCasa5k><br>**Source 3:** Self-made sample floor-plan images (synthetic), for training and testing the RL agent. |
| **Similar to EduAdvisor** | Helps a specific user group make a decision; uses public documents; has guardrails (safety checks); evaluated with clear metrics. |
| **Different from EduAdvisor** | Not a chatbot: the input is a floor-plan image and the output is a 2D layout with reasons. The AI is an RL agent trained in this project, not a ready-made LLM. The reasons come from fixed rules, so they cannot be hallucinated. |
| **Responsible AI Risks** | **Risk 1 — Safety:** the layout looks valid but an exit path is too narrow → people are at risk in an emergency. *Control:* safety is a hard rule, and the tool is advisory only.<br>**Risk 2 — Wrong image reading:** a pillar or exit is missed → seats are placed on top of it. *Control:* the user checks and corrects the grid map before optimising.<br>**Risk 3 — Over-trust:** the organizer accepts the layout without checking it → mistakes go unnoticed. *Control:* show the reason for each criterion (safety, compactness, view, practicality). |

**How it works (simple flow):**
Floor-plan image → grid map → user checks the map → RL agent places items → safety and compactness check (try again if it fails) → final layout + reasons
